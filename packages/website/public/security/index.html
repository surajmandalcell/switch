Security

Last updated November 2, 2026

Switch handles the logins of your AI tools, so security comes first. This page tells you how to report a problem, and how Switch protects your accounts.

Report a vulnerability

Do not open a public issue for a security problem. Report it privately on GitHub, so that it can be fixed before the details are public.

Report privatelyRead SECURITY.md

In your report, include:

  • The Switch version or commit.
  • Your macOS version and your Mac model.
  • The steps to reproduce the problem.
  • What an attacker could do with it.

Do not include credentials, tokens, transcripts, private settings, or logs that are not redacted.

How Switch protects your logins

  • Logins stay in private files that only your macOS user account can read. Staging folders, backups, and account folders all use private permissions.
  • Switch never reads the macOS Keychain or browser cookie stores.
  • The app keeps no raw credential bytes in its own records.
  • Before every switch, the old login is saved. If a change fails, the previous state stays usable and a recovery record is kept.
  • Finding accounts on your Mac makes no network calls and never runs imported hooks. Imported commands and plugins are kept only as data.
  • Switch does not ask for Full Disk Access, Accessibility, or Automation access.
  • There is no proxy, router, or hosted service. Requests go straight from your Mac to each AI service.

Check your download

Each release is signed and notarized by Apple, and each release page lists SHA-256 checksums. To check a download, run this command in Terminal. Then compare the result with the checksums file on the release page.

shasum -a 256 ~/Downloads/Switch-v3.8.2-mac-arm64.zip

Other bugs

For a bug that is not a security problem, open an issue on GitHub. Use made-up data, and remove account names, tokens, auth files, transcripts, and private paths before you post.
